# Notes app fusion example - provenance

Qualification output of RepoFuse 0.6.9 (+ the reviewed file-saving hotfix in
`repofuse/synthesize.py`) fusing two pinned repositories into a small notes
API. Glue and tests were generated by `muse-spark-1.3` on 2026-11-04.

## What happened, exactly

- The model produced an architecture manifest, the glue module
  (`generated/app.py`), and a test file (`test_fused.py`) in 4 model calls.
- The raw AI output FAILED the fixed acceptance test: all 4 tests errored at
  import. Three defects, all in the AI output:
  1. Its dynamic vendor loader accepted the first importable candidate;
     `vendor.microdot` resolves as a PEP 420 namespace package (a directory
     with no `__init__.py`) that has no exports, so `Microdot` was never found.
  2. It assumed `microdot` re-exports `HTTPException` at the package root;
     pinned microdot 2.7.0 keeps it in the `microdot.microdot` submodule.
  3. Importing `vendor.peewee.peewee` created a second peewee module
     instance, so `Note` was not a subclass of the canonical top-level
     `peewee.Model`.
- An assistant repaired those three defects offline, with no further model
  calls. Every repair is labeled `REPAIRED OFFLINE` inline, and the
  unmodified AI bytes are kept in `original-ai/` for comparison.
- The REPAIRED copy passes the fixed acceptance test 4/4 (behavioral, run in
  a namespace sandbox) and the vacuity control (the tests fail when the glue
  is removed, so they genuinely exercise the fusion).

## What this is and is not

- This is a working assistant-repaired example. It is NOT a demonstration of
  unattended AI fusion; the unedited model output does not run.
- Proven behaviors (covered by the fixed acceptance test):
  create a note (`POST /notes` -> 201), list notes (`GET /notes`),
  retrieve one note (`GET /notes/<id>`), 404 for an unknown id,
  persistence across a simulated restart through real peewee/SQLite,
  storage is a real vendored `peewee.Model`, and requests are served by the
  real vendored microdot app object.
- Not implemented and not tested: edit/update and delete. There are no
  PUT/PATCH/DELETE routes. Edit/delete coverage remains an unfinished
  milestone.

## Run it

    cd fused_app
    python3 -m unittest acceptance_test.py   # fixed acceptance test
    python3 test_fused.py                    # model-written tests (repaired)

Requires Python 3.10+. The database path defaults to /tmp/fused.db and can be
set with FUSED_DB_PATH.
