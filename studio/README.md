# RepoFuse Studio - demo UI

A local demo UI for RepoFuse: paste two GitHub repos, describe what you want,
and watch the fusion build unfold. Two modes, both honest about what they are.

## Run it (one command, from anywhere)

    studio/run.sh
    # then open http://127.0.0.1:8317/

Equivalent manual form, from the repo root: `python3 studio/serve.py 8317`.

Python 3.10+, stdlib only. Localhost only. No build step, no dependencies,
no API key, no public hosting.

## Mode 1 - Fuse repositories (LIVE, free stages)

Really clones, pins, license-checks and statically analyzes the repos you
paste, right now, using the actual `repofuse` ingest/analyze pipeline.
Then it STOPS: architecture/glue/test synthesis need a model call, and paid
generation is disabled here (no grant, no key). The UI says so, in so many
words. The header badge reads "LIVE - free stages - 0 model calls".

- The recorded repos (microdot, peewee) are pinned to their exact
  qualification commit SHAs; any other repo is pinned to its current HEAD at
  fetch time and the run says that. No unpinned snapshots.
- `git` must be installed and GitHub reachable for this mode.

## Mode 2 - Replay the recorded run (2026-11-04)

Available only when the inputs match the recorded microdot + peewee notes
build (the button disables otherwise; arbitrary inputs are never dressed up
as the recorded run). Replays the real artifacts: the model's ORIGINAL
generated bytes, the real 4/4 acceptance failure, then the assistant's
labeled offline repair (4/4 + vacuity) and edit/delete extension (7/7).
The badge reads "REPLAY - recorded run 2026-11-04". The timeline keeps the
AI stages and the later assistant stages visually distinct.

## The notes preview is the REAL app

The result screen's notes widget talks HTTP to the actual verified example
app (microdot + peewee + SQLite) which `serve.py` starts from
`examples/notes-app-fusion/fused_app` with `assistant_ext` imported, so
edit/delete really register. Verified end-to-end through the proxy:
POST -> 201, GET list/one, PUT edit, DELETE -> 204, 404 on unknown.
If the backend can't start, the panel says so instead of simulating.

## Server hardening (do not remove)

- Binds 127.0.0.1 only; Host header must be this server (DNS-rebinding
  protection); mutating requests with a cross-origin Origin are refused.
- Static serving is an exact allowlist (the 4 UI files). No listing, no
  traversal, no access to runs/, sources, or anything else on disk.
- /api/fuse accepts POST only and only exact
  `https://github.com/<owner>/<repo>` URLs (ingest re-validates and runs git
  with a scrubbed environment). file:, ssh, other hosts, option injection,
  and extra path segments are refused. Cloned code is READ, never executed
  (analyze is pure static: stdlib ast / regex).
- Bounded: 16 KB fuse bodies, 64 KB note bodies, max 2 concurrent runs,
  last 10 runs retained, clones deleted when a run ends, random run ids.
- The notes backend is spawned by this server on a random loopback port and
  must pass a create/read/delete probe handshake before it is proxied; a
  pre-existing service on any port is never trusted.

## Graph vs plan fidelity (do not remove)

The architecture graph is an ILLUSTRATED, assistant-drawn map of the final
repaired app (captioned as such in the UI). The recorded AI's verbatim plan
(raw architecture-manifest.json content, with its original /users routes)
is embedded in replay-data.js as `manifest` and shown raw in the code panel.
Never present the normalized graph as the recorded plan. Version labels show
the pin commit primarily; peewee's 4.5.3 is a source-declared version at a
post-tag pin, not a tag-commit claim.

## Honesty contract (do not remove)

- No live model calls anywhere; no keys; no claim of live paid generation.
- The unedited AI output FAILED; the working app is assistant-repaired and
  assistant-extended. Unattended AI fusion is the goal, not yet proven.
- "What's real in this demo?" (top right) states all of this in product.

## Video capture controls

- `?speed=4` - replay at 4x. `?autostart=1` - start replay without clicking.
- `?freeze=<state>` - deterministic still: `ingest`, `analyze`,
  `architecture`, `glue`, `verify`, `extend`, `result`, `notes`, or
  `live&run=<run-id>` (renders a finished live run's real events).

## Files

- `serve.py` - local server: static UI, /api/fuse (real free pipeline),
  /api/run/<id> (real event stream), /notes* (proxy to the real app).
- `index.html`, `styles.css`, `app.js` - the UI (vanilla JS).
- `replay-data.js` - recorded-run dataset generated offline from the
  preserved run artifacts (original AI bytes, repaired bytes, extension,
  architecture plan, telemetry, verdicts). Regenerate only from real run
  evidence, never by hand-editing outcomes.
